## Рабочий цикл «оркестратор ↔ Pi»

1. Пользователь формулирует ближайшую цель в этом чате.
2. Оркестратор готовит Pi одно конкретное задание: цель, границы, ожидаемый
   отчёт/артефакты и точный текст запроса. Сначала исследование read-only;
   правки или команды с побочными эффектами отмечаются отдельно.
3. Пользователь передаёт задание Pi в отдельном терминале.
4. Pi работает внутри проекта, читает актуальные AGENTS/OpenSpec/ToDo и
   возвращает фактический отчёт, команды/тесты и изменённые файлы.
5. Пользователь приносит отчёт, diff или ошибки обратно оркестратору.
   Оркестратор проверяет цель, изменения, риски, тесты и persisted outputs;
   спорное проверяется узким follow-up заданием Pi.
6. Непроверенный процесс не превращается в skill. После успешной проверки
   повторяемый процесс оформляется/исправляется как skill; детерминированные
   повторяющиеся операции выделяются в скрипты с тестами.
7. После получения базового качественного результата можно отдельно
   проверить более лёгкую локальную модель; workflow должен оставаться в
   навыках, скриптах и тестах, а не только в памяти модели.

Оркестратор отвечает за постановку задач и независимый review; Pi выполняет
работу в checkout; пользователь передаёт команды и результаты между ними.
Текстовый отчёт Pi не считается достаточным доказательством: важные выводы
подтверждаются файлами, diff, логами и тестами.

## Зафиксированные решения

- Pi уже установлен глобально на Mac Studio. **На MS его повторно ставить не
  нужно**: setup проекта должен обнаружить и использовать существующий runtime.
- На текущем MS `pi --version` вернул `1.0.4`; `pi --help` подтверждает
  параметры `--skill`, `--model`, `--provider`, `--no-session` и поддержку
  загрузки `AGENTS.md`/`CLAUDE.md`.
- На остальных хостах setup должен проверить наличие Pi и устанавливать его
  только если он отсутствует; правила, контекст, инструменты и skills задаются
  индивидуальным harness этого репозитория.
- Project harness находится в `.pi/README.md`, skills — в `.pi/skills/`.
  Команда запуска из корня проекта в отдельном терминале:
  `pi --skill .pi/skills`.
- Уже подготовлены skills: `project-orientation`, `worktree-review`,
  `episode-planning`, `asset-library`, `assembly-handoff`.
- Пользователь выбрал MiniMax M3 для coding-agent. Перед первым prompt
  сверить точный Pi model ID в доступном списке; не подменять другой моделью,
  не менять global config и не сохранять API key в репозитории.
- Текущий локальный frontend выбора и ручного редактирования моделей
  сохраняется. Pi не заменяет его и не обходит согласование provider/model.
- **MCP — основная интеграционная цель проекта.** Pi должен получать проектные
  инструменты через MCP-сервер capcut-studio; `pi-mcp-adapter` поэтому
  релевантен и требует проверки совместимости/обновления, а не считается
  необязательным расширением.
- Telegram-команды — возможный дополнительный интерфейс управления/доступа к
  Pi/MCP. Они не заменяют MCP и не являются первым интеграционным приоритетом.
  Telegram Mini App рассматривается позднее для production.
- До начала реализации сверить актуальный package/version и команды установки
  с `https://pi.dev/`. Не полагаться только на глобальную установку Mac Studio.
