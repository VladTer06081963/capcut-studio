## Ключевой баг (главный из ревью)

**`duration_sec` игнорировался.** Concat-лист содержал только строки
`file`, поэтому каждый исходник проигрывался до конца:

```
declared: 7 × 5.0 с = 35.0 с
actual:   7 × 5.041667 с = 35.29 с
```

Файл при этом фиксировался как **immutable** — то есть неправильный
артефакт уже нельзя было исправить на месте.

**Первое решение было неверным:** я добавил директиву `duration` в
concat-лист, но тест упал — директива `duration` в concat demuxer
меняет только метаданные, медиа не режет. Правильное решение — плюс
обрезка выхода через `-t` (сумма declared-длительностей).

Живой ре-рендер после фикса: **35.04 с** (близко к 35.0 — остаточное
отличие от keyframe-выравнивания при stream copy).

## Что осталось за пределами этой fixation

- **Stream-copy выход не валидируется.** `rc==0` принимается без
  проверки результата. Смешанные resolution/SAR/timebase могут дать
  «warnings-only» битый выход, который будет зафиксирован как
  immutable. Нужен post-render probe (проверка resolution/duration) —
  не реализован.
- **Re-encode fallback не проверен на реальном контенте.** Command
  builder покрыт юнит-тестами; реальный эпизод со смешанными кодеками
  через него не прогонялся.
- **38 файлов `serials/` в репозитории** — это осознанные sample-данные
  (включая одобренный эпизод и `rendered/`-кэш). Оставлены как есть.
