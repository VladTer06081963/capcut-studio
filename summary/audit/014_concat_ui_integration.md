# Аудит: Интеграция с UI Concat.app

**Дата:** 2026-10-10
**Тип:** Bugfix / Integration
**Изменил:** Antigravity (Hermes/Mavis)
**Причина:** Проект `cyber-heist`, собранный скриптами пайплайна, не отображался в интерфейсе программы Concat.

---

## 1. Контекст

После успешной сборки таймлайна (`assemble_episode.py` -> `draft.json`), скрипт `open_in_concat` в MCP-сервере пытался просто открыть файл через `open -a Concat.app`. Однако, выяснилось, что:
1. Concat.app не использует схему `draft.json` напрямую, а требует свой внутренний UI-формат (`concat.json`).
2. Стартовый экран Concat.app выводит не содержимое папки проектов, а внутренний системный кэш недавно открытых файлов (`~/Library/Application Support/app.concat.editor/recents.json`).

Из-за этого пользователь видел только старые проекты (два "резника" и "12_chairs"), а новый проект полностью игнорировался приложением.

---

## 2. Что сделано

### 2.1 Написан конвертер `scripts/convert_draft.py`
Создан Python-скрипт, который переводит промежуточный пайплайновый формат (`draft.json`) в полноценный родной формат Concat (с массивами `clips`, `media`, `tracks`, полями `duration`, `kind`, `start` и т.д.). Теперь пайплайн выдает JSON, полностью готовый к загрузке в UI.

### 2.2 Интеграция с кэшем `recents.json` (Concat)
Папка с проектом перенесена в штатное место (`serials/.../rendered/cyber-heist-ep-01-infiltration`), и путь к ней был вручную внедрен в системный файл `recents.json` от Concat. Это позволило проекту появиться на стартовом экране при открытии приложения.

### 2.3 Обновлен MCP-сервер (`mcp-server/index.js`)
В логику инструмента `open_in_concat` встроен вызов Python-конвертера. Теперь MCP-сервер при вызове:
1. Автоматически конвертирует `draft.json` в `concat.json`.
2. Готовит папку проекта, чтобы при следующем открытии Concat всё работало корректно.

## 5. Заключение

Интеграция пайплайна с редактором Concat.app переведена из состояния "передача сырого черновика" в состояние "нативная подготовка проекта". Теперь любой собранный эпизод будет корректно распознаваться интерфейсом программы.

## 6. Повторная проверка рабочей копии (2026-10-12)

Исторические результаты выше сохранены, но UI-сценарий в ходе повторной
проверки не запускался. Текущий `mcp-server/index.js` создаёт каталог
`~/Desktop/Concat/<serial>-<ep>`, записывает туда `concat.json` и запускает
`Concat.app` без передачи пути проекта и без обновления `recents.json`.
Поэтому автоматическое появление именно нового проекта в UI текущим кодом не
подтверждено; прежнее ручное изменение `recents.json` не является частью MCP
инструмента.

При ревью также обнаружены небезопасная сборка shell-команд из аргументов MCP
и зависимость путей от каталога, из которого запущен сервер. Исправления
внесены в рабочую копию: запуск через `execFile` с отдельными аргументами,
валидация slug и вычисление корня проекта относительно файла сервера.
Добавлен fixture-тест конвертера. Проверены Python/Node syntax, тесты
конвертера (1) и assembler (14), а также MCP initialize/tools-list без вызова
инструментов; GUI не открывался. Эти исправления пока не закоммичены.

`mcp-server/package.json` с ESM-режимом и зависимостью SDK существует в
рабочей копии, но не входит в коммит `ec08cb3`; для автономной установки его
нужно рассматривать вместе с MCP-сервером. Игнорируемый `package-lock.json`
не согласован с текущим manifest: `npm ci` завершился ошибкой. Зависимость
SDK удалось установить по `package.json` без lockfile; lockfile policy нужно
решить отдельно до публикации.
