# Аудит: Интеграция с UI Concat.app

**Дата:** 2026-10-10
**Тип:** Bugfix / Integration
**Изменил:** Antigravity (Hermes/Mavis)
**Причина:** Проект `cyber-heist`, собранный скриптами пайплайна, не отображался в интерфейсе программы Concat.

---

## 1. Контекст

После успешной сборки таймлайна (`assemble_episode.py` -> `draft.json`), скрипт `open_in_concat` в MCP-сервере пытался просто открыть файл через `open -a Concat.app`. Однако, выяснилось, что:
1. Concat.app не использует схему `draft.json` напрямую, а требует свой внутренний UI-формат (`concat.json`).
2. Стартовый экран Concat.app выводит не содержимое папки проектов, а внутренний системный кэш недавно открытых файлов (`~/Library/Application Support/app.concat.editor/recents.json`).

Из-за этого пользователь видел только старые проекты (два "резника" и "12_chairs"), а новый проект полностью игнорировался приложением.

---

## 2. Что сделано

### 2.1 Написан конвертер `scripts/convert_draft.py`
Создан Python-скрипт, который переводит промежуточный пайплайновый формат (`draft.json`) в полноценный родной формат Concat (с массивами `clips`, `media`, `tracks`, полями `duration`, `kind`, `start` и т.д.). Теперь пайплайн выдает JSON, полностью готовый к загрузке в UI.

### 2.2 Интеграция с кэшем `recents.json` (Concat)
Папка с проектом перенесена в штатное место (`serials/.../rendered/cyber-heist-ep-01-infiltration`), и путь к ней был вручную внедрен в системный файл `recents.json` от Concat. Это позволило проекту появиться на стартовом экране при открытии приложения.

### 2.3 Обновлен MCP-сервер (`mcp-server/index.js`)
В логику инструмента `open_in_concat` встроен вызов Python-конвертера. Теперь MCP-сервер при вызове:
1. Автоматически конвертирует `draft.json` в `concat.json`.
2. Готовит папку проекта, чтобы при следующем открытии Concat всё работало корректно.
